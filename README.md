# to Flora

一句祝福 = 一颗星。天上有一百多颗，每颗都是写给 Flora 的一句话；
球可以拖着转，点一颗星能读到那句话。没有第二个功能：没有导航、没有文章、没有页脚、没有表单，
**也没有后端** —— 打开就是这个样子。

画面是一颗浮在星空里、可以拖着转的球：句子是球面上的一颗星，球心是极细线条写成的「to Flora」。
星星按深度分层 —— 正面的亮而大、背面的暗而小，所以转起来能看出是**一颗球**，不是一个圆。
背景是几百颗会闪的星尘，每隔几秒有一道流星划过去。

其中 24 句被特意调得更亮更大（暖金色、十字星芒常亮）。按页面下方的「抽一颗流星」，
会先下一场流星雨，然后随机让其中一颗飞到画面正中，把那句话交到你眼前。

打开页面时：夜幕退去 → 星一颗颗点亮 → 名字浮现 → 弹出一个小窗（落款 **Sylorian 献给 Flora**）。

> **只想把它发布出去？看 [`DEPLOY.md`](DEPLOY.md)。**
> 那份文档是照着做就行的流程：怎么推仓库、怎么连 Cloudflare Pages、怎么确认发成了，
> 每一步都写了「你该看到什么」。本文件是技术参考，解释为什么这么写。

```
浏览器 ──▶ Cloudflare Pages（Hugo 构建，纯静态）
             ↑ 全部内容在构建时就烘进 HTML：没有接口、没有数据库、没有表单
```

## 2. 本地预览

```bash
hugo server --bind 127.0.0.1 --port 1313
```

**版本要求：Hugo ≥ 0.100 都能构建。** 实测过两个版本，产物等价：

| 版本 | 场景 | 结果 |
| --- | --- | --- |
| `0.147.7 extended` | Cloudflare Pages 镜像自带的就是这个 | `exit 0`，无 error 无 warning |
| `0.169.0`（标准版） | 本机 | 同上 |

两者的产物：HTML 只差资源哈希（其余字节完全一致）、CSS 去空白后**逐字节相同**、
JS 只差压缩器的等价改写（`Math.sqrt(x**2+y**2)` → `(x**2+y**2)**.5`）。
所以**不需要设 `HUGO_VERSION`，也不需要 Extended**。

页面里没有任何网络请求：打开 F12 的 Network，除了 HTML / CSS / JS / 字体什么都没有。
所以 `hugo server` 看到的就是线上看到的样子，没有「本地能跑线上不行」这一类问题（除了 `baseURL`）。

## 5. 实现上的几个决定

### 5.1 星星在一颗球上

每条祝福是单位球面（半径 1）上的一个点：

- 用**斐波那契球面**分布（`y` 等距、`θ` 每次加 137.5°），这是球面上等面积散布的标准做法。
  直接按经纬度均匀取样会堆在两极，按斐波那契取样就不会；
- 再叠 ±0.05 弧度的纬度抖动、±0.1 弧度的经度抖动，免得看起来像算出来的点阵；
- **尺寸跟着数量走**：球面上相邻两点的平均间距约 `2R/√n`，所以单颗星的大小按 `1/√n` 收
  （`baseSize(n)`）。85 条暗星 + 24 条亮星时，桌面单颗核心约 10–22px、手机约 6–16px ——
  一百多颗星才不会糊成一团。

每帧把这颗星的单位向量按 `pitch`（绕 X）和 `yaw`（绕 Y）旋转，再做一次弱透视投影：

```js
k = FOCAL / (FOCAL - z)                   // FOCAL = 8，单位是半径
屏幕坐标 = 球心 + (x, y) * 半径 * k
```

于是近处的星略放大、远处的略缩小，加上：

| 深度 | 尺寸 | 不透明度 | z-index |
| --- | --- | --- | --- |
| 最远（背面） | 0.55× | 0.16 | 低 |
| 赤道 | 1.0× | 0.58 | 中 |
| 最近（正面） | 1.47× | 1.00 | 高 |

z-index 跟着深度走，所以球转过来的时候前后的星会正确遮挡 —— 这是「一颗球」和
「一个圆」在观感上最大的差别。

球半径取 `min(球心到左右、上、下)`，并且**给底部两个按钮留出净空**：
1440×900 上是 **384px，直径 768**，底边停在按钮上方 —— 否则球底那几颗星会躲在按钮后面点不到。

### 5.2 为什么还要加一层球面明暗

球面上的均匀分布在**正交投影**下并不均匀：投影到圆盘后，边缘的密度按 `1/√(1-r²)` 上升，
所以只画星星的话，看起来是一圈 —— 上一版的圆环就是这个样子。

解决办法是补上体积信息：一层很淡的球面明暗（左上一点高光、边缘沉下去），
再让星星自己按深度分层。有了这层明暗，边缘的密集就变成了「球的轮廓」，
中间的空就成了「透过球看到的远处」—— 同一堆点，读起来完全不同。

### 5.3 拖动与自转

第一版的转法是「每帧把 yaw 加上固定角速度」，看着像唱片机：整球匀速转、边缘的星飞快、
一上手就觉得机械。现在改成三层：

| 层 | 做法 |
| --- | --- |
| 挂挡（`yawTarget`） | 拖动只改**目标角度**，手怎么走它就怎么加，不直接改渲染用的角度 |
| 跟随（`yaw`） | 每帧向目标角收敛，`1 - e^(-dt·22)` ≈ 45ms 的滞后 —— 有重量感，又不觉得延迟 |
| 呼吸 | 自转速在 `0.72–1.22` 倍之间以约 114 秒周期缓慢起伏，`BASE_SPIN = 0.034 rad/s` |
| 漂移 | 再叠一层 ±0.1 弧度的俯仰漂移（约 100 秒一个来回）：球会轻轻点头，而不是只绕竖轴转 |

这几个数都是可调的，改 `stars.js` 顶部和 `frame()` 里那几行就够。

| 动作 | 实现 |
| --- | --- |
| 抓 | `pointerdown/move/up`，`yawTarget += dx * 0.0062`，`pitchTarget` 夹在 ±0.85 弧度 |
| 甩 | 松手时把最近一次的 `dx` 换算成角速度（夹在 ±5 rad/s），之后指数衰减回自转速度 |
| 刹车 | 抽中一颗星时目标转速变 0，约一秒内平滑停下，方便读字 |

两个容易踩的坑，都写了注释：

- **只有真的开始拖（移动超过 8px）才 `setPointerCapture`**。一按下就抓指针，
  后续的 `click` 目标会变成拖动容器，星星就点不动了；
- **拖完 300ms 内的点击不算点击**，否则甩一下球就会顺手把卡片关掉。

### 5.4 开场动画

| 时间 | 发生什么 |
| --- | --- |
| 0ms | 全黑（`.veil`），只有极远处几颗星尘；整页 `blur(14px)` |
| 120ms | 幕布 1.15s 退场，夜空由暗到亮 |
| 120–1400ms | **聚焦**：整页从 `blur(14px)` 收回 0 —— 像睁开眼睛 |
| 450ms | 「to Flora」浮现：字距从 0.4em 收到 0.14em，从模糊到清晰（2.1s） |
| 550ms–1.7s | 句子星**由球心向外**一颗颗点亮；每颗的延迟按它投影后离球心的距离算 |
| 1.7s | 落款浮现：夜压暗、`to Flora` 四个字退场，只留 **Sylorian / ——— / 献给 Flora** |
| 4.5s | 落款自己淡出，名字回来（点任意处或 Esc 可以提前收） |
| 2.4s | 重排按钮浮出 |
| 全程 | 转速从 0 加速到自转速度 |

落款不是弹窗：没有卡片、没有按钮，就是压在夜空上的一张题字 ——
全屏一层很淡的暗 + 2.5px 模糊，字用「细体拉丁 + 细线 + 衬线中文」三行排出来，
2.8 秒后自己退。球心那个 `to Flora` 在落款期间退到 0 —— 那一刻画面上只有这一句。

### 5.5 卡片跟着星走

同一时间只开一张卡，所以卡片是**一个元素反复用**：

- 打开时定一次「往哪边放」（背离球心的那一侧，放不下就翻到对侧），之后拖球不再来回翻；
- 位置每帧重算：目标点 + 0.3 的跟随系数 —— 于是拖球的时候卡片是**飘**过去的，
  不是硬贴着跳；
- 星转到背面（`front < 0.12`）就自动收掉，不然会看着一张卡挂在球后面；
- 卡片会让开「抽一颗流星」和重排按钮，不会压在它们上面；
- 从星到卡片画一条 1px 的金线，终点是**射线与卡片矩形的第一个交点**
  （写成远端交点的话，线会横穿整张卡 —— 这个我第一版就写错了）。

### 5.6 两级亮度：「抽一颗流星」抽的那些更亮

| | `data/presets.txt`（85 条） | `data/featured.txt`（24 条） |
| --- | --- | --- |
| 星星颜色 | 冷白 / 淡蓝为主 | 暖金 / 玫瑰为主 |
| 光晕强度 | 0.30–0.56 | **0.74–0.96** |
| 核心 | 30% | **40%** |
| 十字星芒 | 很淡（0.22），靠近才张开 | **常亮 0.5** |
| 尺寸 | 基准 | **×1.3** |
| 呼吸动画 | 约 42% 会闪 | 全部会闪 |

亮星是**混进球面随机位置**的（先打散再铺），不会扎堆。

### 5.7 抽一颗流星

按下按钮 → 一场流星雨 → 随机一颗亮星飞到画面正中。

**流星雨**（`meteorShower()` + `spawnMeteor(1)`）四个要点：

| 要点 | 做法 |
| --- | --- |
| **平行** | 每场只抽一个角度（20–30°），所有流星共用 `--ang`，由 CSS 变量统一施加 |
| **从边缘进来** | 起点沿「飞行方向的垂线」铺开，铺的宽度正好等于视口在该方向的投影；再沿反方向退到**刚好在视口外 10px**（逐步试算，不是拍一个 900px 的固定距离 —— 那样缓入动画会让前一秒什么都不出现） |
| **逐渐变多** | 不是随机撒，而是排好的四段：`[5 颗/260ms][7/300][9/280][11/240]`，每毫秒落下 0.019 → 0.046 颗，实测在场数量 1→4→12→21→32 |
| **加速度 + 拖尾回缩** | 头部用 `cubic-bezier(.36,.01,.68,.5)` 沿自身 +X 平移（越飞越快）；尾巴是独立的一层，`scaleX` 从 1 收到 0.06 —— 看上去是**尾巴一路被吸进头部**，而不是整根一起淡掉 |

球也会搭把手：按下的一瞬间给 `state.spin` 一个 1.25 rad/s 的冲刺，
流星和球是同一阵风；星飞出去时球开始刹车，读字的时候画面是静的。
如果球当时是往回（左）转的，流星雨的角度会镜像到 180°−θ，两边永远同向。

然后：

2. 1150ms（流星雨爬到最密时），随机挑一颗亮星：先把它的当前球面位置写成 transform（`transition: none`），
   强制回流一帧，再改成 `(球心, 0.28h) scale(2.6)` —— 于是它**从自己的位置上飞过去**；
3. 卡片跟着以屏幕中线居中打开（`.card.is-hero`，宽 400、正文 20px）；
4. 球心的名字同时退到 `opacity: .1`，画面让给那一句话；
5. 再按一次 = 换一颗；点空白处 / Esc / 点卡片外 = 星飞回球面，按钮文案回到「抽一颗流星」。

飞行期间那颗星由 `it.flying` 标记接管，帧循环跳过它，不会和每帧的 transform 打架。

| 元素 | 动作 | 周期 |
| --- | --- | --- |

| 约 12% 的星尘 | 明暗闪烁 | 3.5–9s |

| 平时流星 | 随机角度划一道（从画面里，不从边缘），45% 概率紧跟第二颗 | **2.6–7 秒一颗** |
| 抽签流星雨 | 平行、从屏幕边缘切进来、密度递增 | 一次约 1.1 秒 32 颗 |

### 5.9 性能：为什么只有一小部分星尘在闪

第一版做了 300 个星尘 + 26 颗星，每个元素各跑一条 CSS 动画。在这台机器的无头浏览器里
（软件渲染，没有 GPU 合成）只有 **36fps**。

逐项关掉测量，瓶颈很清楚：把 326 个元素的动画全停掉，帧率直接到 163fps，
而停掉 JS 的每帧渲染循环只从 45 到 44 —— 也就是说**贵的是 CSS 动画数量，不是 JS 计算**。

改成：星尘只留少数「会闪的」（`--live` 类才挂 animation），其余静止；
星尘整体的极慢自转交给一个图层级的 `transform`。

加了银河和星野之后又测了一轮（同一个软件渲染环境，逐层开关取差值）：

| 改动 | 效果 |
| --- | --- |
| 星尘 170 → **96**（密度交给星野贴图） | **+11fps** |
| 银河去掉 `mix-blend-mode: screen` | +3fps |
| 银河去掉 `mask-image`（改用两块径向渐变画尘埃） | +2fps |
| 银河的呼吸只动 `opacity`，**不动 `scale`**（每帧重采样一张超宽贴图最贵） | 约 +3fps |
| 地平线并进 `.night` 的 `background`，不单独开一层 | +3fps |
| 星野亮度烘进贴图像素，层本身不用 `opacity` | 少一个合成层 |
| 色雾只动 `opacity` + `transform`（合成器就能做） | 2–3fps |

最后 **45–52fps**（这台机器的测量噪声本身就有 ±5）。也就是说整片银河、两层色雾、
近千颗星野加在一起只花了约 6–10fps ——
因为它们是**一次性生成的贴图**，每帧只有两个 `transform` 在动。真机有 GPU 合成会稳在 60。

另外每帧只写 `transform / opacity / z-index` 三个属性，而且**只有真的变了才写**
（缓存上一次的字符串比一下），30 颗星每帧大约 90 次属性写入。

### 5.10 为什么用 DOM 而不是 Canvas

一颗星 = 一个 `<button>`，里面三个 `<span>`（光晕 / 核心 / 星芒）。好处是直接拿到
浏览器像素级的命中测试、键盘焦点、`getBoundingClientRect`；Canvas 得自己实现这一切，
文字还要自己排版。星星的坐标由 JS 算，但动画本身（呼吸、闪烁）全是 CSS，
主线程只负责每帧写 30 个变换。

### 5.11 样式只有一条路：不调 Sass 编译器

`assets/scss/main.scss` 只用「CSS 与 SCSS 都合法」的语法写，所以模板**不调用
`toCSS`**，直接把它的内容换个路径发布成 `/css/main.css`：

```go-html-template
{{ $css = resources.FromString "css/main.css" (resources.Get "scss/main.scss").Content }}
{{ $css = $css | minify | fingerprint "sha256" }}
```

好处：

- 任何 Hugo 版本都能构建（没有 Sass 二进制依赖），产物也不会和源文件不一致；
- 配色与尺寸全走 CSS 自定义属性，改一行就生效。

**为什么不再走 `toCSS`**：Cloudflare Pages 的构建镜像是 Hugo **0.147.7 extended**，
而那个版本的 `toCSS` **没有内置 Dart Sass**，会直接报

```
TOCSS-DART: failed to transform "/scss/main.scss" ... this feature is not available
in your current Hugo version
```

构建当场失败。这份文件本来就不需要编译，绕开编译器既没有副作用，又少一个依赖。

**要写真正的 SCSS 嵌套时**：把上面那两行换成 `toCSS`，并保证构建端有 Dart Sass
（Extended 0.128+ 的新版本自带；0.147 需要自己装 `sass` 或在构建命令里
`npm i -g sass`）。

顺带一提：`hugo.yaml` 里关了 `disableHugoGeneratorInject`。Hugo 默认会往 `<head>` 塞一句
`<meta name="generator" content="Hugo 0.x.y">`，不同版本插的位置还不一样 ——
关掉之后，0.147 和 0.169 构建出来的 HTML 就逐字节一致了。

### 5.12 字体：极细的那一笔是自托管的

- **名字**：Raleway 100（拉丁子集，48KB）。系统里没有真正的 hairline，
  「Segoe UI Light / Helvetica Neue Thin」在不同机器上粗细不一，所以这一个字体自己带；
  同一份文件是可变字体，`@font-face` 里声明 `font-weight: 100 900` 就够了；
- **卡片署名**：Cormorant Garamond 300（22KB），只在第一张卡片打开时才下载；
- **中文**：仍然走系统字体（苹方 / 微软雅黑 / 宋体），不为中文加任何下载；
- 名字的那一行在 `<head>` 里 `preload`，打开时不会闪一下默认字体；
- 全部自托管，**页面运行时零外部请求**（`/ui` 管理面板是唯一的例外，见第 4 节）。

想换字体：把 woff2 放进 `static/fonts/`，改 `main.scss` 顶部那两段 `@font-face` 和
`:root` 里的 `--thin` 即可。

### 5.13 数据：两个纯文本文件，一句一行

没有任何后端。页面上的每一句话都在构建时从两个文本文件读进 HTML：

| 文件 | 条数 | 去处 |
| --- | --- | --- |
| `data/presets.txt` | 85 | 暗星，铺满球面 |
| `data/featured.txt` | 24 | 亮星，也是「抽一颗流星」的抽签池 |

- 一行一条，`#` 开头和空行跳过；**不用引号、不用逗号，直接写句子**，所以那两个文件可以直接编辑；
- 模板用 `readFile` + `jsonify` 把两个数组写成 `window.__FLORA_PRESETS__` / `__FLORA_FEATURED__`；
- 前端**一个网络请求都不发**（打开 F12 的 Network，除了 HTML/CSS/JS/字体什么都没有）；
- 内容经 `textContent` 进入 DOM，**整个前端没有一处 `innerHTML`**，所以句子里的 `<`、`"`、`'`
  既不会破坏 DOM 也不存在注入面。

### 5.14 生日星：一年只有一天

`hugo.yaml` 里 `params.birthday: "11-16"`，`data/birthday.txt` 里一句只在当天才会出现的话。

- 判断发生在**访客浏览器**里（本地时间），不联网、不上报、也不进 HTML 之外的任何地方；
- 日子不对就完全不存在，连 DOM 都不生成。

命中的那颗是全场**唯一「会自己动」的星**，全部纯 CSS，加的都是小元素上的
`opacity / transform`，成本可以忽略：

| 它比别的星多什么 | 做法 |
| --- | --- |
| **更大** | 尺寸 ×1.72，叠上亮星的 ×1.3，约普通星的 2.2 倍 |
| **自带一小片光域** | `halo` 放大到 **380%**，换成暖白 → 暖橙的四段渐变 |
| **更暖的核心** | `#fff8ee` + 暖色双层 `box-shadow`，宽度 42% |
| **星芒会慢慢转** | 十字星芒 ×1.18，**72 秒转一圈** —— 前一刻是十字，过一会儿变成斜的 |
| **整颗缓慢脉动** | `scale 1 ↔ 1.07`，9 秒一个来回（比其余星的呼吸更重） |
| **光环一波一波荡开** | 一个伪元素上叠三圈（1px border + 两层 `box-shadow` 环），9 秒扩到 1.5 倍 |

同时 `.night` 加一个 `is-birthday`，星野和银河各亮 8%——「今天有点不一样」。

> 踩过的一个坑：光域一开始是用大 `blur` + `spread` 的 `box-shadow` 做的，
> 在软件渲染下（再叠上 `opacity`/`scale` 动画）会渲染出**一圈发暗的圆盘**。
> 改成放大渐变本身就好了 —— 更干净，也更便宜。

### 5.15 没有表单，也就没有校验

删掉留言功能的同时，前端的表单、字段校验、`fetch`、`POST`、错误提示全部消失了 ——
现在唯一的输入是「拖动」和「按一下」，没有可以写错的地方。

### 5.16 无障碍与降级

- 名字、星星、按钮都有可读的名字（星星的 `aria-label` 是「祝福 · 署名」）；
- 卡片带 `aria-live="polite"`，读屏会在展开时念出内容；
- Tab 可以逐颗星走一遍：聚焦即展开，回车固定，Esc 收起；
- 系统打开「减少动态效果」时：不自转、不闪、不放流星、落款不做淡入淡出 —— 但**球仍然可以拖**，
  那是用户主动的操作。

### 5.17 背景：色雾、银河、星野、虚化

| 元素 | 做法 | 成本 |
| --- | --- | --- |
| **银河** | 一条 `128vmax × 46vmax` 的带子，`rotate(-22deg)` 斜跨球体，压在球后面。三层径向渐变：外辉光 + 内核 + 两块压暗的尘埃椭圆（**不用 blur、不用 mask、不用 mix-blend-mode**）。呼吸 26s，三层错相位 | 约 2fps |
| **色雾** | 两层巨大的径向色雾：紫的一层亮起来时蓝的一层在退（46 秒一个来回），同时各自缓慢漂移。整片天的色相就在**深紫和蓝之间循环流淌** | 2–3fps |
| **星野** | 1490 颗极暗小星**一次性画进 canvas**，`toDataURL` 之后当两层 `background-image`；之后每帧零成本。远层 1150 颗（0.32–0.95px、0.18–0.52 不透明度），近层 340 颗（0.55–1.35px、0.24–0.66），近层 16% 带十字星芒 | 约 2fps |
| **底色** | 只做「中性的深」（`#131a33 → #03040c`）+ 底部一层冷紫薄雾，颜色交给色雾去给 | 0 |
| **虚化** | ① 开场 `blur(14px)→0`；② 抽中一颗时球和银河 `blur(7px)` + 压暗 55%，卡片和那颗星保持锐利；③ 普通点星不 blur，只让其余的星 `scale .985` + 压暗 24% | ① 一次性 0.85s；② 一次性 0.85s |

虚化只有两个时刻、各 0.85 秒，不是常驻的 —— 这是刻意的：大面积 `filter: blur` 在
没有 GPU 合成的环境里很贵，常驻会一直掉帧。

抽中的那颗星会**从球层搬进 UI 层**再飞（`card.parentNode`），否则它会被球层的
景深滤镜一起糊掉。搬动 = 重新插入 DOM = CSS 动画重启，所以它先加一个
`star--settled` 把入场动画永久掐掉 —— 不做这一步，星飞过去以后会「消失」1.5 秒
（踩过，`--in-delay` 最长 1.5s，期间 opacity 是 0）。

## 6. 排查表

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 打开是空白 / 只有一片蓝 | `baseURL` 不对或 `css` 路径被改写；先看 Pages 的构建日志，再按 F12 看 Console 是否有 404 |
| 名字不是极细字 | `static/fonts/raleway-100-latin.woff2` 没跟着部署，回退到了系统无衬线。检查文件是否存在、`/fonts/` 是否 404 |
| 球不转 | 系统开了「减少动态效果」；或抽签卡片正开着（读字时会刹车）。手动拖仍然有效 |
| 拖球时误触发了点星 | 拖动阈值是 8px；触控板轻扫可能不够，用鼠标按住拖 |
| 星星数量不对 | 改的是 `data/*.txt` 吗？空行和 `#` 开头的行会被跳过 |
| 抽一次没反应 | 看 `data/featured.txt` 是否为空 —— 抽签池为空时按钮什么也不做（暗星不参与抽签） |
| 构建失败 | Cloudflare 镜像自带 Hugo 0.147.7，本站已实测通过；若报 `can't evaluate field Locale` 说明模板被改回了 `site.Language.Locale` |

## 7. 已知边界

- **没有后端，也没有账号**：本仓库就是全部，没有 Worker、D1、密钥或任何凭据。
- **改内容要重新构建**：句子是烘进 HTML 的，改 `data/*.txt` 之后要重新构建才会生效
  （推一次 Git，或本地 `hugo --gc --minify` 再上传）。这正是「纯静态」的代价，也是它简单的原因。
- **手机上的球受宽度限制**：球半径取 `min(半宽, 上边距, 下边距)`，竖屏手机上
  390px 宽把它限制在 179px 左右（直径 358，占满宽度的 92%），上下留出天空。几何结果，不是 bug。
- **性能是按软件渲染测的**：无头浏览器没有 GPU 合成，测出来 50–60fps 已经算宽裕；
  真机上星星的呼吸/闪烁走合成器，主线程只写一百来个变换。
- **窄屏验证方式**：无头浏览器在 390×844 视口 + 触摸模拟下验证（tap 抽签、拖球、卡片不出屏），
  不是真机截图。
